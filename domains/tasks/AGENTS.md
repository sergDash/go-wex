# Модуль задач

Рабочий пример сквозного пути: HTTP-запрос ставит задачу в очередь,
разборщик выполняет её в фоне, состояние видно отдельным запросом. Модуль
проверяет сборку целиком — он получает от реестра и маршруты, и вид работы.

## Маршруты

| Метод и путь | Что делает |
|---|---|
| `POST /api/tasks` | ставит задачу, возвращает номер и статус `queued` |
| `GET /api/tasks/{id}` | отдаёт статус, текст, номер попытки и времена создания и начала; 404, если номера нет |
| `POST /api/tasks/pause` | прекращает захват новых работ |
| `POST /api/tasks/resume` | возвращает разборщик к работе |

## Подкоманда

`app task --text=... [--class=...] [--failUntil=N]` выполняет одну задачу без
служб и печатает строку `{"version":1,"result":"..."}`. Пустой текст —
ошибка, нарочитая ошибка задачи даёт код 1. Версия в строке — протокол
дочернего процесса; формат принадлежит модулю.

Тело задачи: `{"text": "...", "class": "interactive", "failUntil": 1, "delayMs": 2000}`.
Поле `class` задаёт класс работы: `interactive` или `background`; пустое
значение даёт интерактивный класс из правила вида. Фоновая задача ждёт
простоя и не начинается, пока идёт запрос; интерактивная берётся сразу.
Поле `failUntil` задаёт число первых неудачных попыток, `delayMs` — задержку
перед результатом. Оба нужны, чтобы повтор и состояние `running` были видны
снаружи; в обычной задаче они нулевые.

## Правила

- Обработчик работы ничего не пишет клиенту: он возвращает `nil` или ошибку,
  а статус меняет разборщик.
- Ошибка обработчика возвращает работу в очередь с задержкой; после трёх
  попыток статус `failed`.
- Модуль не открывает свой сокет: маршруты идут через общую HTTP-службу.
- Разборщик пока один, и работы он берёт по одной. Пока обработчик ждёт
  задержку, остальные работы ждут своей очереди; пул появится отдельно.
- Интерактивная работа обгоняет фоновую, если обе уже ждут. Порядок виден,
  если поставить обе на паузе, затем продолжить: интерактивная выполнится
  первой.
- Очередь лежит в хранилище: после перезапуска номера и статусы сохраняются.
  Работа, прерванная падением в `running`, выполнится заново с новой попыткой.
