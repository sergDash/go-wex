# Хранилище

`engine/store` — долговечное хранилище JSON-записей: один файл с версией
схемы, миграциями и атомарной записью. Через него данные переживают
перезапуск: очередь, настройки состояния, результаты работ.

## Как устроено

Файл хранит номер версии и записи по коллекциям: имя коллекции → ключ → JSON.
Записи держатся в памяти, а каждое изменение целиком записывается на диск:
временный файл в том же каталоге, сброс, переименование. Сбой оставляет
старую или новую версию файла, но не половину.

## Правила

- Версия — максимальный применённый номер. Миграции идут только вперёд,
  по одной; применённая миграция не редактируется.
- Файл новее кода — отказ при открытии: старый код не записывает поверх
  данных, которых не понимает.
- Сбой записи возвращает память к состоянию файла: иначе следующая удачная
  запись сохранила бы то, что не удалось сохранить сейчас.
- `Put`, `Delete` и `Keys` безопасны из нескольких горутин. Соседний процесс
  не координируется: файл рассчитан на одного писателя.
- Форму записи проверяет тот, кто её читает. Схема коллекций — в
  `doc/schemas/storage.md`.

## Ограничения

Целиком файл переписывается при каждом изменении: это просто и предсказуемо,
но не годится для больших объёмов. Табличное хранилище с частичной записью
появится, когда объём данных этого потребует.
