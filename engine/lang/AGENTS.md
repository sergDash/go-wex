# Словари переводов

Пакет читает каталог словарей, сливает локали и отдаёт тексты по контекстам.
Это механизм, а не модуль: он одинаково годится интерфейсу, ответам модулей
и записям, которые приложение готовит для другого получателя (например, для
модели). Модулей словарь не знает. Оба потребителя уже есть: страница читает
тексты через маршруты, а модуль `domains/log_ru` берёт фразу для записи
в журнал.

## Раскладка каталога

```
lang/ru-RU/common.json     подписи самой страницы
lang/ru-RU/httpapi.json    раздел интерфейса «Связь с сервером»
lang/ru-RU/jobs.json       раздел «Работа в очереди»
```

Каталог задаётся настройкой `lang.dir` (по умолчанию `lang`), базовая локаль —
`lang.base` (по умолчанию `ru-RU`). Без раздела `lang` в настройках переводов
нет: маршруты не объявляются, механизм не подключается.

Имя файла — контекст: раздел интерфейса или набор записей, который
запрашивают вместе. Ключи внутри контекста плоские и короткие, называют смысл,
а не тег: `title`, `lead`, `empty`, `connect_button`. Два контекста могут
называть свои ключи одинаково — в ответе они лежат под контекстом.

## Маршруты

| Адрес | Что отдаёт |
|---|---|
| `GET /api/lang` | базовую локаль и список доступных: код и как язык называет себя |
| `GET /api/lang/ru-RU` | все контексты языка |
| `GET /api/lang/ru-RU/jobs,events` | только названные контексты |

Адрес читается как путь к каталогу: за ним действительно лежат файлы, а
перечень контекстов — перечень разделов.

## Слияние и запасной путь

Порядок выбора языка: точный код (`de-AT`), затем язык без региона (`de`),
затем базовая локаль. Ответ всегда называет фактический язык в поле `lang`
и запрошенный в `requested`: клиент ставит `<html lang>` по фактическому,
иначе страница заявит язык, на котором текста нет.

Недостающий в локали ключ берётся из базовой локали, а сам ключ попадает
в `missing`. На экране остаётся осмысленный текст, а расхождение словарей
видно по ответу и не требует гадать.

Без перечня контекстов отдаётся объединение файлов обеих локалей: иначе
страница на языке без перевода раздела потеряла бы раздел целиком.

## Поведение при ошибках

- Сломанный JSON и отсутствующая базовая локаль — ошибка запуска: приложение
  не должно подниматься с половиной словаря.
- Неизвестный контекст и неверная форма языка — отказ входа (400): опечатка
  в имени раздела видна сразу, а не превращается в пустой раздел.
- Ошибка чтения файла при запросе — отказ 500 с путём к файлу.

## Файлы читаются на каждый запрос

Словари лежат рядом с приложением и правятся без пересборки, как статика
интерфейса. Если читать их один раз при запуске, правка перевода потребует
перезапуска. Файлы килобайтные, поэтому цена — работа операционной системы;
память по паре «язык, контекст» добавляется, если замеры покажут, что нужно.

## Что не решено

- Ответы словаря пока не помечены `Cache-Control: no-cache`: простой маршрут
  отдаёт данные, а заголовки ставит движок. Из-за этого правка перевода может
  не доехать до открытой страницы. Пути описаны в `TODO` функции `Register`
  в `http.go`; решается вместе с политикой кэширования ответов модулей.
- Разметка внутри перевода (например, `<code>` вокруг адреса запроса) не
  поддерживается: подставляется только текст. Это отдельное решение о том,
  разрешать ли разметку в словаре.
- Сверки ключей шаблона со словарём нет: ключ, сочинённый в разметке, даст
  пустое место. Проверку стоит добавить, когда словарей станет больше.

## Файлы

| Файл | Назначение |
|---|---|
| `lang.go` | каталог, список локалей, слияние с базовой локалью, запасной путь |
| `http.go` | маршруты словаря и отказ входа |
