# Мысли

Заметки на будущее. Не правила и не сценарии; здесь можно думать вслух.
Решения из этого файла попадают в `doc/coding/engine.md` только после того,
как проверены на деле.

## Трейты

В Rust трейт — именованный набор методов с реализацией по умолчанию,
ассоциированными типами и ограничениями обобщений; реализация объявляется
явно, через `impl Trait for Type`. В Go ближайший аналог — интерфейс: набор
методов, который тип удовлетворяет неявно. Методов по умолчанию и
ассоциированных типов в Go нет; вместо них встраивание и обобщения.

Что стоит взять:

- узкие интерфейсы на стороне потребителя: интерфейс объявляется там, где его
  используют, а не там, где реализуют;
- композиция встраиванием вместо наследования;
- обобщения вместо ассоциированных типов, где они действительно нужны.

Чего стоит избегать: одного общего интерфейса на все возможности. Когда
появится второй потребитель, `Registry` можно разбить на узкие:
`HTTPRegistrar`, `JobRegistrar`, `ListenRegistrar`, `CommandRegistrar`.
Модуль тогда получает только то, что объявил.

Решение отложено: сначала службы и работы, потом видно, какие интерфейсы
действительно нужны.

## ECS

ECS — для предметной области, не для ядра движка. Ядро расширяется реестром
модулей; ECS внутри ядра дал бы неявный поток данных и скрытый порядок систем,
то есть ровно то, от чего мы уходим.

Для мира с разнородными объектами ECS полезен именно расширяемостью: модуль
добавляет компонент и систему и не меняет существующие. Набросок отдельного
пакета `domains/world`:

```go
type Entity uint64

type World struct {
	next    Entity
	systems []System
	// компоненты по типу
}

type System interface {
	Name() string
	Run(context.Context, *World) error
}

func (w *World) Add(e Entity, c any)
func (w *World) Each[T any](fn func(Entity, T)) // обход по типу компонента
```

Порядок систем задаётся списком при сборке мира; модуль объявляет свои системы
и их место. Компоненты — данные, системы — поведение, сущность — только номер.

Проверка расширяемости: второй модуль добавляет компонент и систему, не меняя
код первого. Если для этого нужно править чужой модуль — это не ECS, а реестр
с красивым названием.

Цена: неявное чтение и запись компонентов, порядок систем как скрытая
зависимость, отладка через несколько шагов. Смягчение — явные запросы, один
писатель на компонент, журнал работы.

Решение отложено: сначала службы и работы, потом мир как отдельный модуль.
