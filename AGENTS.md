# go+wex — скелет веб-приложения

Этот файл — индекс для агентов. Он отвечает на три вопроса: что это за проект,
как его запустить и куда идти за правилами. Подробности лежат в `doc/`
и `.agents/rules/`, а не здесь.

## Что это

Образец приложения, в котором бэкенд написан на Go, а интерфейс — на wex
(реактивная библиотека поверх jQuery). Прикладные проекты, включая TNS,
приводятся к этой структуре. Репозиторий — единственная линия развития,
ветка `main`.

## Запуск и проверки

```
cd web-server && go run ./cmd/app     # фронтенд найдётся в ../web-interface
cd web-server && go build -o ../bin/app ./cmd/app
./bin/app                             # запуск из корня, фронтенд в web-interface
cd web-server && go vet ./...
cd web-server && go test ./...
```

Сервер ищет `web-interface` в текущем каталоге, затем в `../web-interface`;
явный путь задаётся флагом `-web`. Внешних Go-зависимостей нет. jQuery, wex
и less.js лежат в `web-interface/vendor/`; обращений к CDN в проекте быть
не должно.

## Карта каталогов

| Путь | Назначение |
|---|---|
| `bin/` | собранные бинарники, в git не попадают |
| `web-server/` | Go-модуль: `cmd/app`, `internal/httpapi`, доменные пакеты |
| `web-interface/` | фронтенд: разметка, `app.js`, `style.less`, `vendor/` |
| `doc/coding/` | правила кода |
| `doc/game/` | механики конкретных игр |
| `doc/schemas/` | формы данных: хранилище, настройки, обмен |
| `.agents/rules/` | правила работы агента в этом проекте |
| `.agents/memory/` | запомненная информация между сессиями |

## Правила, которые действуют всегда

1. Данные идут одним путём: сервер отдаёт JSON → `app.js` кладёт его в стейт →
   шаблон выводит стейт. Прямая правка DOM и `innerHTML` из логики запрещены.
2. Ответ API всегда в конверте: успех — `{"result": ...}`, ошибка —
   `{"error": "..."}`. Клиент разбирает его деструктуризацией и сначала
   проверяет `error`.
3. `internal/httpapi` не содержит игровых и предметных правил: обработчик только
   разбирает запрос, вызывает доменный пакет и кодирует ответ.
4. Поля JSON и имена полей стейта совпадают. Меняя структуру ответа, правь
   `internal/httpapi` и `web-interface/app.js` вместе.
5. Стили пишутся на Less: переменные, миксины, вложенность. Селектор —
   одно слово, область задаётся вложенностью. Цвета в разметке и JS не задаются.
6. Документация обновляется в той же правке, что и правило, которое она
   описывает.
7. Документы пишутся по принципу пирамиды Барбары Минто: сначала главное
   утверждение, ниже — обоснование. Вывод должен читаться с первой строки
   раздела, а не собираться из текста к его концу.
