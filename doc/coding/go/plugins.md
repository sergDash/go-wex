# Расширения: плагины без динамической загрузки

Дата: 2026-11-22

Короткое правило: **плагин в этом проекте — это отдельный пакет Go, собранный
вместе с приложением, либо отдельный процесс с явным протоколом. Это не `.so`
или `.dll`, которую кладут в каталог, и приложение подхватывает её на ходу.**

Правило записано, чтобы отсечь recurring идею «бросим библиотеку в папку — и
всё заработает». Ниже — почему динамическая загрузка не подходит и что делать
вместо неё.

## Почему динамическая загрузка не подходит

**Пакет `plugin` в Go.** Требует совпадения версии компилятора, набора флагов
сборки и всех зависимостей до коммита. Не работает на Windows. Плагин нельзя
выгрузить из памяти. Паника в плагине роняет весь процесс. Типы через границу
должны быть собраны из одних и тех же пакетов с теми же путями, иначе
приведение типа не срабатывает. На каждую комбинацию «ОС + архитектура +
версия приложения» нужна своя сборка плагина.

**`.so`/`.dll` через cgo.** Своя пачка проблем: нестабильный двоичный интерфейс,
ручное владение памятью по обе стороны границы, паника Go не переживает переход
через C, отладчик не видит стек через границу, на каждую платформу своя сборка
и свои правила загрузки.

**Распространение.** Пользователь получает бинарник приложения; плагин должен
быть собран ровно под него. Любое расхождение версий даёт либо отказ загрузки,
либо несовпадение структур и порчу данных вместо внятной ошибки.

**Отладка и покрытие.** Профилировщик и стек вызовов не показывают код плагина
так, как код приложения; покрытие тестами плагин не включает.

**Это не решает настоящую задачу.** Добавление возможности — это маршрут, экран,
пункт настроек, миграция и права на запись в хранилище. Загрузка кода — самая
простая десятая часть работы; остальные девять десятых всё равно требуют явной
регистрации и манифеста.

## Что делать вместо

**Встроенный модуль.** Пакет в `domains/<модуль>` с одной точкой
входа вида `Register(mux *http.ServeMux, deps Deps)`. Точка сборки перечисляет
модули явным списком. Модуль не заводит собственных глобальных переменных и
получает зависимости аргументами. Пункты интерфейса модуль отдаёт данными
(например, список разделов в JSON), а не правкой чужой разметки.

**Отдельный процесс.** Бинарник запускается по требованию, обменивается
сообщениями по явному протоколу и сообщает свою версию при старте, чтобы
стороны могли отказаться от несовместимого обмена. Падение такого процесса не
задевает ядро, язык реализации не важен, обновление сводится к замене файла.
Годится для тяжёлых разовых задач и для чужого кода.

Правило выбора простое: **можно оформить пакетом — пакет; нельзя оформить
пакетом — процесс.** Динамическая загрузка не выбирается ни в одном случае.

## Чего расширение не определяет само

Модуль не придумывает свой формат ответа и свои коды ошибок: действует общий
конверт `{"result": …}` / `{"error": …}` и общие коды состояния. Имена полей
JSON совпадают с полями стейта во фронтенде. Расширение, которое вводит
собственные правила обмена, ломает совместимость сильнее, чем отсутствие
расширения.
