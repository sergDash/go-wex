# Правила кода

Общие требования к коду — в `.agents/rules/coding_style.md`
и `.agents/rules/engineering_mindset.md`. Здесь только то, что относится
к этому проекту и его слоям.

## Файлы раздела

| Файл | О чём |
|---|---|
| `plugins.md` | расширения: встроенный модуль или отдельный процесс, но не динамическая загрузка `.so`/`.dll` |

Формы данных — хранилища, настроек и обмена — описаны в `doc/schemas/`,
а не здесь: этот раздел про устройство кода, а не про форму данных.

## Поток данных

Код описывает превращение данных: что пришло, что с этим сделали, что ушло
дальше. Состояние видно в явном виде: стейт страницы на фронтенде, структуры
в доменных пакетах на сервере.

- Функция получает данные аргументами и возвращает результат.
- Сложная структура получает имя и комментарий: какие поля есть, что означает
  каждое, кто владелец.
- Побочный эффект очевиден по имени функции: `save`, `render`, `log`.

## Результат и ошибка

Сервер и клиент придерживаются одного порядка: сначала проверяется ошибка,
затем используется результат.

В Go это обычное `result, err := ...` с проверкой `err` сразу после вызова.

В JSON ответ API всегда имеет конверт:

```json
{"result": {"ok": true, "status": "сервер отвечает"}}
{"error": "что именно не так"}
```

На клиенте ответ разбирается деструктуризацией, и `error` проверяется первым:

```js
const { result, error } = body;
if (error) {
    throw new Error(error);
}
```

Пустой объект, `null` или голое значение вместо конверта не отдаются: клиент
не должен угадывать форму ответа по коду состояния.

## Слои

| Пакет | Что можно | Что нельзя |
|---|---|---|
| `web-server/cmd/app` | флаги, поиск фронтенда, запуск сервера | маршруты, доменные правила |
| `web-server/internal/httpapi` | маршруты, разбор входа, конверт, коды ответов | игровые правила, вычисления |
| `web-server/internal/<домен>` | структуры, правила, вычисления, хранение | импорт `net/http` |

Доменный пакет не знает, откуда пришли данные: из HTTP, из теста или
из консольной команды.

## Обработчики

1. Разобрать вход.
2. Проверить его и вернуть ошибку сразу при неверных данных.
3. Вызвать доменную функцию.
4. Записать конверт и код ответа.

Текст ошибки пишется для человека, читающего интерфейс. Внутренние
подробности уходят в журнал через `log.Printf`, а не в ответ.

## JSON

- Имена полей — `camelCase`, совпадают с полями стейта во фронтенде.
- Структура результата объявляется рядом с обработчиком.
- Пустой список отдаётся как `[]`, а не `null`.
- Время — RFC 3339.

## Статика

Фронтенд лежит в `web-interface/` и читается с диска. `httpapi` принимает
`fs.FS` и не знает, откуда взялась файловая система. Путь ищет `cmd/app`:
явный `-web`, затем `web-interface`, затем `../web-interface`. Встроенной
копии в бинарнике нет: проект запускается рядом со своим фронтендом.

## Ошибки и журнал

- `log.Fatalf` допустим только в `main`.
- В библиотечных пакетах ошибка возвращается наверх, а не печатается.
- Ошибку, которую некуда вернуть, логируют с указанием операции.

## Имена

- Пакеты — короткие, без подчёркиваний: `httpapi`, `game`, `store`.
- Файлы — по предмету: `health.go`, `chat.go`, `world.go`, а не `utils.go`.
- Тесты — рядом с кодом, `*_test.go`; проверяют поведение домена.
