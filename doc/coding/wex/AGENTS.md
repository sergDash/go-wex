# wex: библиотека интерфейса

## Что подключено

- `interface/vendor/jquery.min.js` — jQuery 3.7.1.
- `interface/vendor/wex.min.js` — сборка wex из репозитория
  `https://github.com/wemmbley/wex`, коммит `2e7a2f3`.
- `interface/vendor/less.js` — Less 4.6.6, компилирует `style.less`
  в браузере.
- Порядок подключения в `index.html` обязателен: jQuery, затем wex, затем
  код приложения. wex расширяет `window.$` и без jQuery не работает.
  Less подключается отдельно в `<head>` и на wex не влияет.

Книга и примеры в `book/` используют CDN-адреса. В проекте внешних адресов
нет: те же файлы лежат в `interface/vendor/`. Примеры из книги
запускаются как есть, но ссылки на CDN в них — часть учебного материала,
а не образец для проекта. Версии и причины их выбора описаны в
`interface/vendor/AGENTS.md`.

## Как устроена страница проекта

1. Разметка экрана лежит в `<template id="...">` в
   `interface/index.html`.
2. `interface/app.js` создаёт стейт через `$('#id').state({...})`
   и вызывает `mount()`. С этого момента шаблон подписан на стейт.
3. Серверные данные приходят через `fetch` в конверте
   `{"result": ...}` или `{"error": "..."}`. Ответ разбирается
   деструктуризацией, `error` проверяется первым, поля результата
   попадают в стейт через `view.update({...})`, и wex сам перерисовывает
   изменившиеся узлы.
4. Пользовательские действия меняют стейт обработчиками `.on(...)` или
   через `w-bind`; DOM руками не правится.

## Правила проекта

- Стейт — единственный источник того, что видно на экране. Если значение
  нужно показать, оно должно быть полем стейта.
- Прямые операции с DOM (`addClass`, `text`, `attr`, `innerHTML`) в логике
  запрещены: для этого есть `w-class`, `{{ }}`, `w-src`, `w-value`.
- Ответ API не разбирается в шаблоне. `app.js` приводит его к полям стейта,
  шаблон выводит готовые значения.
- Один экран — один шаблон и один модуль логики. Когда экранов станет
  несколько, каждый получит файл в `interface/screens/`, а `app.js` останется
  точкой сборки: создание стейта, подключение экранов, запуск.
- Общий стейт между экранами появляется только при реальной необходимости.
  Владелец стейта — один модуль; остальные получают данные через него,
  а не создают вторую копию.
- `w-static` применяется к блокам, которые не зависят от стейта: так они
  выпадают из цикла перерисовки.

## Обновление библиотеки

```
cp ~/src/wex/dist/wex.min.js interface/vendor/wex.min.js
rm -rf doc/coding/wex/book
cp -r ~/src/wex/book doc/coding/wex/book
cp ~/src/wex/docs/api.md doc/coding/wex/api.md
```

После замены `wex.min.js` проверить стартовую страницу и обновить коммит
в этом файле.
