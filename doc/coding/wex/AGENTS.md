# wex: библиотека интерфейса

## Что подключено

- `interface/vendor/jquery.min.js` — jQuery 3.7.1. wex 3 работает без него:
  у библиотеки свой мини-`$`, который создаётся, если `window.$` свободен.
  В проекте jQuery подключён первым, wex его подхватывает, и `$` на странице
  один.
- `interface/vendor/wex.min.js` — сборка из форка `sergDash/wex`, ветка
  `fix/all`, коммит `a584ca0`. Строка версии внутри — `3.1.1`, как и у
  официальной сборки, поэтому ориентир — коммит и путь, а не версия.
- `interface/vendor/less.js` — Less 4.6.6, компилирует `style.less`
  в браузере.
- Порядок подключения в `index.html` обязателен: jQuery, затем wex, затем
  код приложения. Less подключается отдельно в `<head>` и на wex не влияет.

Книга и примеры в `book/` используют CDN-адреса. В проекте внешних адресов
нет: те же файлы лежат в `interface/vendor/`. Примеры из книги
запускаются как есть, но ссылки на CDN в них — часть учебного материала,
а не образец для проекта. Версии и причины их выбора описаны в
`interface/vendor/AGENTS.md`.

## Чем 3.x отличается от прежней сборки

- jQuery не требуется: внутри свой мини-`$` с выборкой, событиями и
  делегированием. Настоящий jQuery не мешает — wex предпочтёт его.
- `w-for` умеет ключ атрибутом `w-key="row.id"`; `traceby` остался.
  Ключи локальны списку.
- Атрибуты `w-*` после разбора вырезаются из DOM. Логика не должна искать
  их в разметке.
- `view.update(fn)` перерисовывает только затронутое через прокси;
  для изменений мимо прокси нужен `view.update(true)`.
- Обработчик `w-on` получает нативный `Event`, а не `jQuery.Event`.
- Директивы: прежняя форма `directive(name, compile, affect)` сохранена
  слоем совместимости, действующая — объектная, с `mounted`, `updated`,
  `unmounted`. Справочник — `api.md`, отличия — `Переход-на-3.md`.

Часть книги описывает прежний интерфейс (например, `$el` в `compile`).
Читать её можно, но за точной формой лучше идти в `api.md`.

## Как устроена страница проекта

1. Разметка экрана лежит в `<template id="...">` в
   `interface/index.html`.
2. `interface/app.js` создаёт стейт через `$('#id').state({...})`
   и вызывает `mount()`. С этого момента шаблон подписан на стейт.
3. Серверные данные приходят через `fetch` в конверте
   `{"result": ...}` или `{"error": "..."}`. Ответ разбирается
   деструктуризацией, `error` проверяется первым, поля результата
   попадают в стейт, и wex сам перерисовывает изменившиеся узлы.
4. Пользовательские действия меняют стейт обработчиками `.on(...)` или
   через `w-bind`; DOM руками не правится.

## Свои директивы

Одна директива в проекте уже есть: `w-stick` в `app.js` держит прокрутку
таблицы очереди в конце. Она показывает принятый способ: разметка
объявляет поведение, логика по-прежнему меняет только стейт, а работа
с размерами живёт в директиве рядом с элементом.

## Правила проекта

- Стейт — единственный источник того, что видно на экране. Если значение
  нужно показать, оно должно быть полем стейта.
- Прямые операции с DOM (`addClass`, `text`, `attr`, `innerHTML`) в логике
  запрещены: для этого есть `w-class`, `{{ }}`, `w-src`, `w-value`.
- Ответ API не разбирается в шаблоне. `app.js` приводит его к полям стейта,
  шаблон выводит готовые значения.
- Один экран — один шаблон и один модуль логики. Когда экранов станет
  несколько, каждый получит файл в `interface/screens/`, а `app.js` останется
  точкой сборки: создание стейта, подключение экранов, запуск.
- Общий стейт между экранами появляется только при реальной необходимости.
  Владелец стейта — один модуль; остальные получают данные через него,
  а не создают вторую копию.
- `w-static` применяется к блокам, которые не зависят от стейта: так они
  выпадают из цикла перерисовки.

## Обновление библиотеки

```
cp ~/src/wex-sergDash/dist/wex.min.js interface/vendor/wex.min.js
rm -rf doc/coding/wex/book
cp -r ~/src/wex-sergDash/education/Книга doc/coding/wex/book
cp ~/src/wex-sergDash/education/API.MD doc/coding/wex/api.md
cp ~/src/wex-sergDash/MIGRATION.MD doc/coding/wex/Переход-на-3.md
```

После замены `wex.min.js` проверить стартовую страницу и обновить коммит
в этом файле и в `interface/vendor/AGENTS.md`.
