# Доработать

Список замеченных доработок движка. Сюда попадает то, что нашлось при работе
прикладного проекта (TNS) и относится к самому go-wex: приложение обошло
проблему у себя, но обходной путь повторять в каждом проекте не нужно.

Запись — это задача, а не решение. Она отвечает на четыре вопроса: что
случилось (с датой и проектом), почему это движок, а не приложение, что
сделать и как проверить, что сделано. Решённая запись не удаляется, а
помечается «сделано» с датой и ссылкой на правку.

## Статика отдаётся без Cache-Control — сделано 2026-11-27

**Сделано 2026-11-27, коммит `033259a`.** Обёртка `revalidate` стоит в `New`
над файловым сервером: ответы статики получают `Cache-Control: no-cache`,
`Last-Modified` остаётся от `FileServer`. Проверка — `TestStaticRevalidate`
в `engine/httpapi/server_test.go`: заголовок, метка времени и ответ `304`
на повторный запрос. Сценарий — SC-34 в `doc/capabilities/scenarios.md`;
правило записано в `engine/httpapi/AGENTS.md` и в разделе «Транспорт»
`doc/coding/engine.md`. Дымовой прогон: `curl -I /app.js` отдал
`Cache-Control: no-cache` и `304` на `If-Modified-Since`, после `touch`
файла тот же запрос вернул `200` с новым телом. В TNS обходной путь
`revalidate` больше не нужен — его стоит убрать при следующей сверке.

**Что случилось.** 2026-11-27, при работе над TNS. Правка `interface/app.js`
не доезжала до открытой страницы: раздел показывал старый экран, пока
браузер не сбросили через `Ctrl+Shift+R`. Причина — `engine/httpapi` отдаёт
статику обычным `http.FileServer`, а он выставляет только `Last-Modified`.
Без `Cache-Control` браузер применяет эвристическую свежесть (доля от
возраста файла) и берёт файл из кэша, не спрашивая сервер. Интерфейс при
этом читается с диска и правится без пересборки — то есть режим, ради
которого статика не вшита в бинарник, ломался на ровном месте.

**Почему движок.** Ответ статики формирует `engine/httpapi/server.go`,
приложение на это не влияет никак: свой заголовок оно поставить не может.

**Что сделать.** Помечать ответы статики `Cache-Control: no-cache` (не
`no-store`: файл кэшируется, но каждая страница сверяется с сервером).
Обёртка на `http.FileServer` в `New`:

```go
s.mux.Handle("GET /", revalidate(http.FileServer(http.FS(assets))))

func revalidate(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Cache-Control", "no-cache")
		next.ServeHTTP(w, r)
	})
}
```

`Last-Modified` у `FileServer` остаётся, поэтому сверка стоит одного запроса
и отвечает `304`, если файл не менялся.

**Проверка.** `curl -I http://127.0.0.1:<порт>/app.js` — в ответе есть
`Cache-Control: no-cache`; повторный запрос с `If-Modified-Since` из
`Last-Modified` отвечает `304`. В браузере: открыть страницу, поправить
`interface/app.js`, нажать F5 — правка видна без сброса кэша.

**Где уже сделано у нас.** TNS обошёл это у себя: `engine/httpapi/server.go`
в дереве TNS содержит ту же обёртку `revalidate`. Теперь такая обёртка есть
и в движке, поэтому при следующей сверке расхождение снимается.
