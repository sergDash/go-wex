# Словари переводов

Каталог текстов интерфейса и не только. Разложен по локалям, внутри локали —
по контекстам: один файл — один раздел или один набор записей, которые
запрашивают вместе.

```
lang/
  ru-RU/
    common.json      подписи самой страницы, название языка
    httpapi.json     раздел «Связь с сервером» и «Поток порций»
    jobs.json        раздел «Работа в очереди»
    log_ru.json      фразы модуля записи в журнал
  en-GB/
    common.json
```

Каталог читает движок (`engine/lang`), а тексты приходят в интерфейс через
`GET /api/lang/<язык>/<контексты>`: страница кладёт их в стейт и выводит
шаблоном. Тот же каталог может взять модуль, которому нужна фраза для ответа
или для записи, — файлы одни на обе стороны.

## Правила

- Имя файла — контекст; имя локали — BCP 47 (`ru-RU`, `en-GB`), а не `ru_RU`:
  так его понимают браузер, `Accept-Language` и `Intl` без перевода туда-обратно.
- Ключ называет смысл, а не тег: `title`, `lead`, `empty`, а не `title_h1`.
  Пара коротких слов на целый абзац — норма.
- Ключи плоские: контекст уже даёт первую половину адреса, поэтому внутри
  файла префикс не нужен.
- Базовая локаль — `ru-RU`. Незнакомый язык сводится к ней, а недостающий
  ключ берётся из неё же: пустого места на экране быть не должно.
- Каждый язык называет себя сам (`common.json`, ключ `language_name`):
  переключатель должен быть понятен тому, кто уже видит чужой язык.
- Добавить язык — положить каталог. Кода это не касается.
- Сломанный файл останавливает запуск приложения: словарь с половиной текстов
  хуже, чем понятная ошибка.

## Разметка в переводах

Значение может содержать тег `<code>` — так в пояснениях выделяются имена
пакетов, адреса запросов и ключи. Страница выводит такие тексты директивой
`w-html`, потому что `{{ }}` пишет только текст: тег в значении иначе
показался бы словами.

Правила, которые надо знать, чтобы не искать их в коде:

- Элемент в разметке остаётся пустым: `<p class="note" w-html="texts.jobs.note"></p>`.
  `w-html` заменяет содержимое целиком, и любая заглушка внутри исчезает
  вместе с ним — в том числе когда значение пустое. Проверено 2026-11-27.
- Символы `<`, `>` и `&` вне разметки пишутся как `&lt;`, `&gt;`, `&amp;`.
  В нынешних текстах таких символов нет, поэтому экранирование не нужно;
  правило существует на случай, если появится текст вроде «меньше 5».
- Разрешена не любая разметка: значение проходит через `sanitizeSvg` из wex.
  Он вырезает `script`, `iframe`, `object`, `embed`, `style`, `foreignObject`,
  `animate`, `set`, снимает атрибуты `on*` и `href`, не начинающиеся с `#`.
  Поэтому внешние ссылки в переводе не поставятся, а `code`, `b`, `em`
  работают. Это защита от случайной разметки, а не полноценный санитайзер.
- Переводы — доверенные файлы проекта. Если когда-нибудь значения начнут
  приходить из формы или из внешнего каталога, `w-html` для них использовать
  нельзя: там нужен текст и `{{ }}`.
- Пропавший ключ не превращается в пустое место: при загрузке страница
  сверяет шаблон со словарём и перечисляет отсутствующее в строке отказа.
  Проверка ловит и опечатку в ключе, и забытый контекст.
