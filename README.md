# go+wex

Скелет веб-приложения: сервер на Go и интерфейс на wex — реактивной библиотеке
поверх jQuery. Это образец структуры, по которому приводятся в порядок
прикладные проекты (игровые приложения вроде TNS и подобные им).

Проект не является библиотекой и не публикуется как модуль. Его задача —
показать, где живёт каждый вид кода и как данные проходят от сервера до DOM.

## Запуск

Требуется Go 1.27 или новее. Внешних зависимостей у сервера нет.

```
go run ./cmd/app                  # http://127.0.0.1:8080, фронтенд из бинарника
go run ./cmd/app -web ./web       # фронтенд читается с диска
go build -o bin/app ./cmd/app
```

Флаг `-web` нужен при правке HTML/CSS/JS: файлы берутся с диска, пересобирать
Go не требуется. Без флага работает встроенная копия из `web/`, поэтому
собранный бинарник можно переносить без каталога `web/`.

## Проверки

```
go vet ./...
go test ./...
```

Тестов пока нет: `go test` проверяет, что все пакеты собираются.

## Структура

| Путь | Назначение |
|---|---|
| `cmd/app/` | точка входа: флаги, выбор источника фронтенда, запуск сервера |
| `internal/httpapi/` | маршруты, разбор запросов, JSON-ответы |
| `internal/` | доменные пакеты приложения (появятся по мере роста) |
| `web/` | фронтенд: `index.html`, `app.js`, `style.css` |
| `web/vendor/` | локальные jQuery и wex, без CDN |
| `doc/coding/` | правила написания кода и документация библиотек |
| `doc/game/` | описания игровых механик конкретных проектов |

## Документация
