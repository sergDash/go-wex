# go+wex

Скелет веб-приложения: сервер на Go и интерфейс на wex — реактивной библиотеке
поверх jQuery. Это образец структуры, по которому приводятся в порядок
прикладные проекты (игровые приложения вроде TNS и подобные им).

Проект не является библиотекой и не публикуется как модуль. Его задача —
показать, где живёт каждый вид кода и как данные проходят от сервера до DOM.

## Запуск

Требуется Go 1.27 или новее. Внешних зависимостей у сервера нет.

```
go run ./engine/app
go build -o bin/app ./engine/app
./bin/app
```

Адрес сервера, каталог интерфейса, путь к файлу хранилища и пороги простоя
берутся из `config/httpapi.json`. Сервер ищет интерфейс в указанном каталоге,
затем на уровень и два уровня выше. Путь можно переопределить флагом
`-web <каталог>`. Флаг также удобен при правке фронтенда: файлы читаются
с диска, пересобирать Go не нужно.

## Проверки

```
go vet ./...
go test ./...
```

Тесты лежат рядом с кодом: `go test ./...` проверяет поведение, а не только
сборку.

## Структура

| Путь | Назначение |
|---|---|
| `bin/` | собранные бинарники |
| `engine/` | движок: точка сборки, настройки, службы, работы, хранилище, HTTP |
| `config/` | настройки приложения: адрес сервера и каталог интерфейса |
| `domains/` | модули предметной области |
| `interface/` | разметка, скрипты, стили, сторонние библиотеки |
| `schemas/` | машинно-проверяемые схемы |
| `doc/coding/` | правила написания кода и документация библиотек |
| `doc/game/` | описания игровых механик конкретных проектов |
| `doc/schemas/` | формы данных: хранилище, настройки, обмен |
| `doc/capabilities/` | сценарии: что движок обязан выдержать |
| `doc/experience/` | разборы падений: что случилось и что уцелело |
| `.agents/rules/` | правила работы агента в проекте |
| `.agents/memory/` | запомненная информация между сессиями |

## Документация

`AGENTS.md` в корне — индекс для агентов и людей. Правила кода разложены по
`doc/coding/*/AGENTS.md`, книга wex — в `doc/coding/wex/book/`,
правила работы агента — в `.agents/rules/`.
