# Интерфейс

Статика приложения: `index.html`, `app.js`, `style.less` и `vendor/`.
Читается с диска; сервер не вшивает её в бинарник. Так файлы можно править
без пересборки — это удобнее при разработке.

## Правила

- Данные идут одним путём: сервер отдаёт JSON → `app.js` кладёт его в стейт →
  шаблон выводит стейт. Тексты подписей — такие же данные: они приходят из
  `GET /api/lang/<локаль>` в стейт (`texts`, `lang`) и выводятся шаблоном.
  Русский текст в разметке остаётся только у разделов, которые ещё не
  переведены на словарь.
- Интерфейс объясняет, а не только показывает: у каждой возможности движка
  есть короткое пояснение рядом с кнопкой, которая её запускает.
- Рядом с заголовком секции — имя пакета движка, который она показывает:
  `engine/httpapi`, `engine/jobs`. Слой интерфейса подписывается как
  `interface`, модуль предметной области — путём пакета (`domains/log_ru`):
  так видно, что секция показывает модуль, а не механизм. Так видно, что секция демонстрирует механизм, а не страницу.
- Полный текст сценария остаётся в `doc/capabilities/scenarios.md`;
  в интерфейсе только короткое пояснение, второй копии быть не должно.
- Панель собрана секциями: одна возможность движка — одна секция
  с пояснением, именем пакета, данными и кнопкой.
- Первая секция объясняет разницу между механизмом движка и модулем:
  механизм — часть движка, модуль — то, что к нему подключается и объявляет
  возможности. Без этого подписи `engine/...` читаются как названия модулей.
- Обновление идёт по кнопке. Опрос не заводится, пока не сделан канал
  обновлений (SC-16): иначе панель закрепит способ, от которого сценарий
  отказывается.
- `w-on` не передаёт аргументы: обработчик получает событие DOM, а не
  значения из шаблона. Значение пункта берут из его `data-*` атрибутов
  (`data-select`, `data-value`), а не из `click:fn(row.id)` — в аргумент
  придёт объект события.
- Выпадающие списки сделаны из своих элементов (`select → selected +
  options`), а не из браузерного `<select>`: открытие, выбор и подсветка
  лежат в стейте, разметка только объявляет их через `w-on` и `w-class`.
  Клик мимо закрывает список: слушатель на документе пропускает клики
  внутри `.select` и сбрасывает открытые списки в стейте.
- Вид списка задаётся вторым классом: `simple`, `searchable`, `multiple`.
  Общая база и две добавки лежат отдельными группами вне `.panel`, чтобы
  список был стилизован в любом родителе. Ширину задаёт родитель: `.select`
  заполняет его, хост `x-select` получает ширину классом на месте.
- Повторяющийся список оформляется компонентом `x-select`: один шаблон,
  своё состояние у каждого экземпляра, данные приходят пропсами
  (`:items`, `:value`), выбор уходит родителю событием `@change`.
- В компоненте обработчик `w-on` получает в `this` DOM-элемент, а не вью:
  внешняя функция метода вызывается с вью, поэтому `emit` отправляют через
  сохранённую ссылку (`var component = this;` во внешней функции). Значение
  пункта берут из `event.currentTarget.dataset`, потому что `w-on` сам
  подставляет найденный элемент.
- Поле поиска внутри списка держит текст в стейте через `w-bind`: без этого
  перерисовка списка по вводу сбрасывает набранное. Ввод не очищается и при
  повторном открытии: список пересобирается по тому, что уже набрано.
  Фокус ставит директива `w-focus` при появлении поля, иначе после открытия
  списка нужно целиться мышью.
- Словарь читается до `mount`: заголовки берутся из стейта, поэтому сначала
  текст, потом первая отрисовка. До `mount` стейт — обычный объект
  (`view.state` появляется после отрисовки), поэтому заполнение идёт через
  переменную, а не через вью. Отказ словаря страницу не снимает: причина
  пишется в `langError` отдельной строкой, потому что общий `failure` стирает
  успешный снимок данных.
- `<html lang>` ставится по фактическому языку ответа, а не по запрошенному:
  сервер сводит незнакомый язык к знакомому и называет его в поле `lang`.
- Текст с разметкой (например, `<code>` вокруг имени пакета) выводится
  директивой `w-html`, а не `{{ }}`: подстановка пишет только текст, и тег
  показался бы словами. Элемент при этом остаётся пустым — `w-html` заменяет
  содержимое целиком, поэтому заглушка внутри него не выживает. Правила
  разметки, экранирования и санитайзера — в `../lang/AGENTS.md`.
- Пропавший ключ словаря не оставляет пустого места: при загрузке `checkTexts`
  сверяет шаблон со словарём и перечисляет отсутствующие ключи в строке
  отказа. Проверка нужна именно из-за `w-html`: заглушку в разметку
  не поставить, а пустое место взглядом не отладить.
- Ключ называет смысл, а не тег: `title`, `lead`, `empty`, `connect_button`.
  Контекст уже даёт первую половину адреса.
- Прямая правка DOM и `innerHTML` из логики запрещены.
- Поток порций читается `EventSource`; объект соединения живёт вне стейта
  (это транспорт, а не данные страницы), а пришедшие порции кладутся в стейт
  и рисуются шаблоном.
- Стили пишутся на Less: переменные, миксины, вложенность.
- Предметных правил и вычислений здесь нет: только отображение состояния
  и отправка запросов.
- Сторонние библиотеки лежат в `vendor/` и подключаются локально; обращений
  к CDN быть не должно.

## Файлы

| Путь | Назначение |
|---|---|
| `index.html` | разметка страницы и панелей демо |
| `app.js` | стейт, запросы, отображение |
| `style.less` | исходник стилей |
| `../lang/` | словари текстов: локаль → контекст → ключи |
| `favicon.ico` | зелёная точка вкладки: без файла браузер получает 404 на `/favicon.ico` |
| `vendor/` | jQuery, wex, less.js |
