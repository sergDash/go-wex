Классы работ и захват сделаны: у Job и Spec есть Class (interactive, background), Enqueue принимает класс, пустой берётся из Spec, затем фон. Claim(ctx, now, allowed []Class) берёт только разрешённые классы; пустой allowed — пауза по расписанию. Порядок: interactive раньше background, внутри класса — AvailableAt, затем ID. Dispatcher.SetAllowed задаёт набор вручную; по умолчанию разрешены оба класса. StoreQueue сохраняет класс в записи и при открытии переводит старые записи без класса в background.

Осталось для SC-06 и SC-07: engine/clock (Now, After, Tick, подставляемые часы) и engine/schedule (Allowed(lastActive, now) []Class по порогам из данных). Подключить к разборщику: перед захватом брать набор из расписания, а не только SetAllowed. Нужен источник последней активности; вероятно, HTTP-служба отмечает запрос, либо хранилище хранит метку.

SC-07 дополнительно требует, чтобы фон не начинался, пока запрос активен: счётчик активных запросов или семафор, который исключает background на время интерактивной работы. Классы и фильтр для этого готовы, учёта активности ещё нет.

Долговечная очередь: состояние пишется одной записью store.Put; при добавлении расписания фильтр класса меняется в одном месте — queue.Claim и earlier.
