Репозиторий go-wex: https://github.com/sergDash/go-wex, public с 2026-11-22, remote origin https, ветка main отслеживает origin/main. Локальный каталог — ~/src/go-wex (переименован пользователем из go+wex). Последний коммит на момент записи — addb265 «Движок: раскладка engine/domains, настройки, службы и работы», запушен. Go 1.27, внешних зависимостей нет, bin/ в .gitignore.

Раскладка: engine/ — движок (app, config, core, service, jobs, httpapi); engine/app — package main и единственное место, импортирующее domains; domains/health — модуль с GET /api/health; interface/ — статика; config/httpapi.json — настройки HTTP-службы; schemas/httpapi.schema.json; doc/{coding,game,schemas,capabilities,experience}; Мысли.md. AGENTS.md есть в каждом каталоге.

Запуск из корня: go run ./engine/app; сборка: go build -o bin/app ./engine/app; запуск: ./bin/app. Проверки: go build ./..., go vet ./..., go test ./..., go test -race ./... — зелёные. Дымовой запуск: /api/health отдаёт {"result":{"ok":true,"status":"сервер отвечает"}}, / отдаёт 200, SIGTERM освобождает порт, повторный запуск сразу занимает его.

Настройки: config/httpapi.json с server.addr и interface.dir. Путь по умолчанию config/httpapi.json, переопределяется флагом -config; -web переопределяет каталог интерфейса. engine/config.LoadHTTPAPI проверяет пустые обязательные поля и запрещает неизвестные ключи (DisallowUnknownFields). Адрес и каталог в main не задаются.

Стандарт модуля: engine/core — Module{Name, Register(Registry)}, Registry{HTTP(method, path, Handler)}, Handler func(*http.Request) (any, error). Модуль только объявляет; конверт result/error и код ответа пишет engine/httpapi. HTTP-служба реализует service.Service (Name/Start/Stop), открывает сокет синхронно, Stop вызывает Shutdown. engine/service.Group запускает службы в порядке списка, останавливает в обратном, общий срок 5 с; app использует signal.NotifyContext (SIGINT/SIGTERM).

engine/jobs: Kind, Job, Queue, Spec, Registry, MemoryQueue, Dispatcher. Постановка только кладёт работу; Claim переводит в running и увеличивает Attempts; ошибка — Retry с задержкой, после MaxAttempts — Fail; паника обработчика превращается в ошибку. Step — один шаг для тестов, Run — цикл с тикером 1 с и подсказкой. Очередь в памяти; долговечная появится с engine/store. Разборщик в app не запущен: ни одного вида работ ещё не объявлено.

Интерфейс: interface/index.html, app.js, style.less, vendor. jQuery 3.7.1 (не 4.0.0: wex проверен на 3.x), wex коммит 2e7a2f3, less.js 4.6.6. Статика читается с диска и не вшивается, чтобы править файлы без пересборки. Данные идут путём JSON → стейт → шаблон; прямая правка DOM из логики запрещена.

Документация: doc/coding/engine.md — устройство движка, словарь (модуль, внутренняя служба, работа, очередь, разборщик, исполнитель, пул, семафор, мьютекс, таймер, тикер, расписание, событие, проекция, подсказка, подкоманда, дочерний процесс), стандарт модуля, очередь, время, журнал, запуск себя, раскладка, чего не делать. doc/capabilities/scenarios.md — сценарии SC-01…SC-18; doc/capabilities/AGENTS.md — формат сценария (ситуация, ожидаемо, средства, проверка). doc/experience/AGENTS.md — формат разбора падения (что случилось, что разрушилось, что сохранилось, что изменить); файлов опыта пока нет. doc/schemas — правила схем. doc/coding/go/plugins.md — плагин это пакет или отдельный процесс, не динамическая загрузка .so/.dll. Мысли.md — отложенные трейты (узкие интерфейсы на стороне потребителя) и ECS (для предметной области, набросок domains/world; проверка: второй модуль добавляет компонент и систему, не меняя первый).

Предстоит: engine/store с миграциями и проверкой версии схемы, долговечная реализация jobs.Queue; engine/clock и engine/schedule с порогами простоя (5/10 минут и дальше); engine/journal — журнал работы с ротацией и перехватом паник на границах; запуск разборщика как службы при появлении первого вида работ; полный доменный пример (список и создание) для потока экран → API → домен → JSON → стейт → DOM; перенос механик TNS в doc/game по одной; развилка узких интерфейсов Registry после второго потребителя.
