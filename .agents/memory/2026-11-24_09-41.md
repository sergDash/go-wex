Состояние go-wex на 2026-11-24. Сделано: раскладка движка закрыта. app — два режима: без аргументов поднимает службы, с первым аргументом выполняет подкоманду до чтения настроек. config — server.addr, interface.dir, store.path, schedule.rules, journal (path/maxSize/keep), схема версии 4. core — Module, Registry с HTTP/Job/Service/Command, Handler, CommandHandler, Error. service — Service, Group, Pausable. jobs — Job с Kind/Class/Payload/Attempts/AvailableAt, Spec, Registry, NewMemoryQueue и OpenStoreQueue, Dispatcher-служба, Claim по разрешённым классам и сроку, порядок interactive раньше background, пауза, SetAllowedFunc, Get, повторы и журнал. store — JSON-файл, версия, миграции вперёд, атомарная запись, коллекции. clock — Real и Manual. schedule — Rule и Allowed по простою. activity — Meter активных запросов и последней активности. journal — Writer, Discard, Journal с ротацией и службой. listen — TCP и UDP как службы, паника на соединении, Addr. process — Registry подкоманд и Service процесса с отдельной группой, TERM затем KILL, вывод и код в журнал, restart/failed/stopped. httpapi — маршруты, конверт, коды через core.Error, учёт активности, паника в журнал.

Модули: health (GET /api/health), tasks (POST/GET задач, pause/resume, работа task.run, подкоманда task --text), demo (GET /api/demo, POST/GET demo.echo, TCP и UDP эхо на 127.0.0.1:0, процесс demo child, подкоманда demo). demo включён в moduleList по умолчанию.

Сборка: реестр собирает маршруты, работы, службы и подкоманды; службы стартуют journal → службы модулей → разборщик → HTTP, останавливаются в обратном порядке. Store-очередь переживает перезапуск; работа в running при открытии возвращается в очередь, поведение «хотя бы один раз». Фон ждёт простоя и не начинается, пока идёт запрос. Журнал пишет done/retry/fail/panic и вывод процесса. Подкоманды не читают настройки и не поднимают службы.
