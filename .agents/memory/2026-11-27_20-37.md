Состояние go-wex на 2026-11-27 вечером. Переводы интерфейса сделаны по согласованной схеме, всё в main и отправлено в origin.

Механизм engine/lang: каталог lang/<локаль>/<контекст>.json, контекст = файл и раздел интерфейса, ключи плоские и короткие. Маршруты GET /api/lang (базовая локаль и список языков с самоназваниями), GET /api/lang/ru-RU (все контексты), GET /api/lang/ru-RU/jobs,events (названные). Цепочка de-AT → de → ru-RU, недостающий ключ берётся из базовой локали и попадает в missing, ответ сообщает фактический язык в lang и запрошенный в requested. Неизвестный контекст даёт 400, сломанный словарь останавливает запуск. Файлы читаются на каждый запрос — правка перевода без перезапуска. Настройка lang {dir, base} со умолчаниями lang и ru-RU, схема httpapi-11.

Интерфейс: все секции на словаре (контексты common, core, httpapi, service, jobs, events, gate, interface, log_ru). Словарь читается до mount; стейт до mount — обычный объект (view.state появляется после отрисовки), поэтому он собран в переменную state0, и первая версия падала на view.state.langError. Динамические строки собираются в app.js функциями word(texts, контекст, ключ, запасное) и fill(шаблон, значения) по местам {1}, {2}; в шаблоне тот же fill доступен фильтром. Статусы работ приходят кодами queued/running/done/failed/cancelled и переводятся по ключу, неизвестный код показывается как есть. Даты форматируются локалью ответа.

Разметка в переводах: <code> в словаре, вывод через w-html на пустом элементе (подстановка {{ }} пишет только текст). Проверено: содержимое элемента w-html заменяется целиком, заглушка внутри исчезает и при пустом значении — поэтому вместо заглушек checkTexts в app.js сверяет шаблон со словарём и перечисляет отсутствующие ключи в красной строке отказа (пример: «нет текстов: jobs.empty»). Санитайзер wex sanitizeSvg вырезает script, iframe, object, embed, style, foreignObject, animate, set и снимает on* и href не на #; внешние ссылки в переводе не поставятся, code/b/em работают. Символов < > & в текстах нет, экранирование не нужно; правило на будущее записано. Вид code задан в style.less: плашка с фоном акцента, моноширинный, white-space: nowrap. Правила в lang/AGENTS.md, interface/AGENTS.md, engine/lang/AGENTS.md и комментарием в разметке.

Модуль domains/log_ru (package logru) — второй потребитель словаря: POST /api/log_ru/write берёт фразу written из lang/ru-RU/log_ru.json, пишет её в журнал работы (source log_ru, kind written) и отдаёт текст с языком. Словарь обязателен: без раздела lang модуль не собирается. Каталог открывается в обоих режимах (openCatalog в app), deps получил lang.

Открыто и не сделано: серверные фразы вне словаря (сообщения ошибок модулей, причина отказа службы, health.status) остаются русскими — нужен код вместо текста и перевод на клиенте; ответы словаря без Cache-Control no-cache, TODO в engine/lang/http.go описывает два пути (пометить все ответы модулей или дать простым маршрутам заголовки); второго языка нет намеренно — движок показывает механизм, а не каталог; ключи, используемые из app.js через word(), проверкой checkTexts не покрыты (у них есть запасные значения); SC-16 (обновления без опроса) и SC-18 (тексты опыта) по-прежнему не сделаны.

Проверки: go build/vet/test/test -race и node --check зелёные; страница снималась headless Firefox через обёртку с медленной картинкой (обычный снимок берётся до загрузки словаря и показывает пустой экран); временные страницы для опытов (attr-test, esc-test, inline-test, html-test, fallback-test) создавались в interface/ и удалялись после проверки.
